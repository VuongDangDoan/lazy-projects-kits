## Operating Rules

1. **Context:** mỗi phiên đọc `knowledge/L3-session/active-context.md` + ticket đang làm; L0 `knowledge/L0-global/` luôn áp; L1 `knowledge/L1-domain/<module>-domain.md` theo module; legacy ⇒ L2 scan.
2. **Source:** luôn đi qua `_source/<repo>/` (không `../<repo>/`). Code chỉ sửa trong phạm vi ticket. KHÔNG tự commit/push repo `_source/` — người làm. `scripts/typecheck-source.sh` phải PASS trước khi bàn giao Build.
3. **Phase gates:** BA →G1→ SA →G2→ Planner →G3→ Build (implement → self-review → self-QC, tối đa 3 vòng, không dừng giữa chừng) →G4→ E2E →G5. Agent không bao giờ tự vượt G1–G5; lỗi SPEC (AC/contract sai) luôn trả về người, không "sửa" trong Build. Chi tiết + luồng rút gọn (trivial / bug-fix / schema-touch): `.agents/orchestration.md`.
4. **Output contract:** mọi artifact theo schema trong `.agents/contracts/` — thiếu trường bắt buộc = chưa xong.
5. **Doc Sync:** mọi lần sửa code/kiến trúc kết thúc bằng Doc Sync Plan (`.agents/contracts/doc-sync.schema.md`); mọi thay đổi `_source/` có self-review trong `tasks/reviews/`.
6. **Legacy:** đụng code cũ mà chưa có `knowledge/L2-legacy/scans/<module>-legacy-scan.md` ⇒ chạy `/legacy-scan` trước, không đoán.

## Commands

Gõ `/` để xem danh sách; mô tả từng lệnh nằm trong chính file lệnh. Pipeline chính: `/ba → /sa → /planner → /dev|/fe|/mobile → /e2e`; tiện ích: `/status`, `/build`, `/review`, `/qc`, `/release`, `/legacy-scan`, `/switch-module`.

## What Claude Must NOT Do

- Sửa `_source/` ngoài phạm vi ticket; tự commit/push repo `_source/`
- Bàn giao Build khi `scripts/typecheck-source.sh` chưa PASS
- Vượt gate G1–G5 không có người duyệt; đoán hành vi legacy
- Đổi naming convention mà không cập nhật `knowledge/L0-global/naming-convention.md`
- Drop/rename bảng hay endpoint cũ mà không có ADR trong `architecture/decisions/`
- Cập nhật doc sau khi sửa code mà không có Doc Sync Plan (trừ tier tự duyệt)

## 7. Operating Rules

### 7.1 Context Loading — MANDATORY

```
L0 (always load):    knowledge/L0-global/
L1 (per module):     knowledge/L1-domain/[module]-domain.md
                     knowledge/L1-domain/module-integration-map.md
L2 (if legacy):      knowledge/L2-legacy/scans/[module]-legacy-scan.md
L3 (per session):    knowledge/L3-session/active-context.md
                     tasks/tickets/[TICKET-ID].md
```

### 7.2 Source Code Access Rule

Claude is both the **reader** and the **implementer** of source code. The `_source/<repo>/` symlinks point to the real repos — edits via the symlink land directly in those repos.

- Always reference and edit source through `_source/<repo>/src/`.
- For **read-only exploration** (legacy scan, pattern discovery): use Read/Grep through `_source/`.
- For **implementation** (`/dev`, `/fe`, `/mobile`): write final code into `_source/<repo>/...` within ticket scope. Run `scripts/typecheck-source.sh` before declaring handoff.
- Commits to source repos are made by the human. Claude never auto-commits in `_source/<repo>`.
- The workspace repo is committed separately and only contains agent artifacts.

### 7.3 Legacy Rule — NEVER SKIP

- If a task touches legacy code → **legacy scan is required** before writing any code
- If `knowledge/L2-legacy/scans/[module]-legacy-scan.md` does not exist → run `/legacy-scan` first
- Never infer legacy behavior — read `_source/` or ask the human

### 7.4 Phase Gates — humans approve at G1–G5, agents chain inside a phase

The pipeline runs in 5 phases with a human gate at each boundary (see `.agents/orchestration.md` §1):

```
Phase 1 BA → G1 → Phase 2 SA → G2 → Phase 3 Planner → G3
→ Phase 4 Build (implement → self-review → self-QC → fix loop) → G4
→ Phase 5 E2E → G5
```

- **Inside a phase, agents chain automatically.** The Build phase self-audits: implement → self-review → self-QC → fix findings, max 3 rounds, with NO human stop between steps.
- **Agents never cross a phase gate (G1–G5) without explicit human approval.**
- **SPEC defects always escalate** — wrong AC or wrong contract goes back to the human (Phase 1/2), never gets "fixed" inside Build.

### 7.5 Output Contract — No field may be skipped

All output must conform to schemas in `.agents/contracts/`.
Missing any required field = output is incomplete, cannot be handed off.

### 7.6 Documentation Sync

Whenever a code-touching agent (Dev / FE Dev / Mobile Dev / SA) changes source code or architecture artifacts, it MUST output a **Doc Sync Plan** at the end of the pass.

- Contract: `.agents/contracts/doc-sync.schema.md` — code → doc mapping and protocol.
- **Auto-approve tier:** trivial diffs matching the schema's §Auto-approve criteria are applied and reported without a human stop; everything else waits for approval at G4.
- The self-review step enforces it: a Build pass with no Doc Sync Plan fails review.

### 7.7 Lightweight Flows — skip phases safely

Pick the right protocol from `.agents/orchestration.md` §2:

- **Trivial protocol (§2.1):** typo / CSS / copy → 1-line ticket → Phase 4 (implement → self-review only) → G4.
- **Bug-fix protocol (§2.2):** defect, no spec change → narrow ticket → Phase 4 full self-audit → G4 → Phase 5 only if a critical user path.
- **Schema-touch protocol (§2.3):** API/DB shape change, no new business rules → Phase 2 → Phase 3 → Phase 4 → Phase 5 if FE consumes it.

Hard quality gates (always hold, §2.4): every `_source/` change gets a self-review in `tasks/reviews/`; every legacy touch needs a fresh-enough scan; every code change produces a Doc Sync Plan; every contract change goes through `/sa`.

## 10. What Claude Must NOT Do

- Edit `_source/<repo>/` outside the scope defined in the active ticket
- Auto-commit or push in any `_source/` repo — humans control source-repo commits
- Declare a Build handoff before `scripts/typecheck-source.sh` passes for the changed repo
- Infer legacy behavior without reading `_source/` or completing a legacy scan
- Cross a phase gate (G1–G5) without explicit human approval — inside a phase, agents chain freely
- Change naming conventions without updating `knowledge/L0-global/naming-convention.md`
- Drop or rename legacy tables/endpoints without an ADR in `architecture/decisions/`
- Update documentation after a code change without a Doc Sync Plan (auto-approve tier excepted)
